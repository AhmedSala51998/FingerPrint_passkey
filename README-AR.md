# هوية — PHP + MySQL + Passkeys

مشروع مستقل لإنشاء الحساب والدخول بمفتاح مرور باستخدام WebAuthn. PHP 8.1 أو أحدث، MySQL 5.7+/MariaDB 10.4+، وامتدادات pdo_mysql وopenssl وmbstring وsession. لا يحتاج Node أو Composer عند التشغيل. مكتبة lbuchs/WebAuthn مرفقة بترخيص MIT، مثبتة على commit fb4bcee0ea8a5bc25e5dc358172d65bf15b5f419.

## تشغيل XAMPP
1. شغّل Apache وMySQL.
2. انسخ مجلد passkey-system إلى C:\xampp\htdocs\passkey-system.
3. استورد database/schema.sql من phpMyAdmin. ينشئ قاعدة passkey_portal والجداول. للاستضافة المشتركة، أنشئ القاعدة من لوحة الاستضافة واحذف سطري CREATE DATABASE وUSE من SQL ثم استورد الباقي داخل قاعدتك.
4. انسخ private/config.example.php إلى private/config.php، واضبط اسم القاعدة والمستخدم وكلمة السر. إعداد التطوير المرفق يستخدم root بلا كلمة سر، ويجب تغييره للاستضافة.
5. افتح http://localhost/passkey-system/ على الكمبيوتر. localhost هنا اسم النطاق، لا تضف مسار المشروع إلى origin أو rp_id.

## تشغيل الهاتف أو الاستضافة
- يلزم نطاق HTTPS صالح. الدخول من الهاتف إلى عنوان IP محلي عبر HTTP لن يشغّل Passkeys. localhost على الهاتف يعني الهاتف نفسه، وليس الكمبيوتر.
- عدّل origin إلى الأصل الكامل مثل https://auth.example.com (يشمل المنفذ إن وجد، ولا يتضمن المسار)، وعدّل rp_id إلى auth.example.com بلا https ولا مسار ولا منفذ.
- origin ثابت، لا يُشتق من Host أو رؤوس البروكسي.
- أنشئ مفاتيح جديدة لنطاق الإنتاج؛ مفاتيح localhost أو نطاق آخر لا تنتقل تلقائيًا له. تغيير مسار المجلد على نفس الأصل لا يغيّر RP ID.
- ارفع كل الملفات، بما فيها ملفات .htaccess. على Apache امنع الوصول لمجلدي private وdatabase؛ الحماية مرفقة. على Nginx أو أي سيرفر يتجاهل .htaccess امنع الوصول لهما من إعداد السيرفر قبل النشر. لا ترفع اختبارات أو نسخ قاعدة حقيقية إلى مسار عام.
- اضبط توقيت جلسة قاعدة البيانات UTC لعرض تواريخ الاستخدام بشكل متسق.

## الاستخدام
- حساب جديد: الاسم واسم مستخدم فريد واسم المفتاح، ثم تأكيد الجهاز. لا يُنشأ حساب في القاعدة إلا بعد تحقق التسجيل.
- احفظ رموز الاسترداد خارج الهاتف؛ تُعرض مرة واحدة وتُحفظ تجزئاتها فقط، وكل رمز يُستخدم مرة واحدة.
- تسجيل الدخول: يختار الجهاز مفتاح المرور المناسب، ويوقّع تحديًا جديدًا؛ السيرفر يتحقق من التوقيع والمفتاح العام وRP ID والأصل والتحدي وحضور المستخدم والتحقق منه.
- يمكنك إضافة مفاتيح أخرى وحذفها. لا يمكن حذف آخر مفتاح. التعديلات الحساسة تحتاج دخولًا حديثًا خلال خمس دقائق. أعد الدخول عند انتهاء المهلة.
- بعد الاسترداد أضف مفتاحًا جديدًا ثم احذف مفتاح الجهاز المفقود. رموز الاسترداد لا تلغي المفاتيح القديمة تلقائيًا.
- الجلسة تنتهي بعد 30 دقيقة من عدم النشاط.
- أسماء المستخدمين ليست بريدًا موثقًا ولا إثبات هوية مدنية. لا يوجد إرسال بريد أو استعادة عن طريق البريد في هذه النسخة.
- نقل قاعدة البيانات ونسخها الاحتياطي مسؤولية صاحب الاستضافة. لا توجد بيانات دخول افتراضية أو حساب مسؤول مخفي.

## ما الذي يُخزن؟
users: هوية حساب عشوائية واسم المستخدم والاسم وتاريخ الإنشاء.
credentials: معرف مفتاح المرور والمفتاح العام والعداد واسم المفتاح والتواريخ.
recovery_codes: تجزئة الرموز فقط.
rate_limits: تجزئة عنوان الشبكة/نوع العملية وعدّاد زمني للحد من المحاولات.
لا يوجد تخزين لبصمة الإصبع أو صورة بصمة أو بيانات الوجه أو المفتاح الخاص. البروفايل يعرض حرف الاسم وأسماء المفاتيح وآخر استخدام، ولا يعرض صورة بصمة مزيفة.

## حدود مهمة
- يدعم الأجهزة والمتصفحات الحديثة التي تدعم Passkeys، مثل Safari على iPhone وChrome على Android، بعد إعداد قفل الجهاز ومزوّد مفاتيح المرور. Windows Hello ومفاتيح المرور على الكمبيوتر مدعومة بحسب المتصفح والجهاز.
- التحقق المطلوب userVerification=required. نظام التشغيل قد يستخدم البصمة أو Face ID أو رمز القفل. الموقع لا يستطيع فرض البصمة فقط أو معرفة الإصبع أو الشخص الذي سجّل البصمة داخل الهاتف.
- المفاتيح قد تتزامن عبر حساب Apple/Google حسب إعداد المستخدم. ليست نظام حضور يضمن جهازًا واحدًا أو موقعًا جغرافيًا أو يمنع مشاركة رمز القفل.
- كاميرا الهاتف ليست قارئ بصمة آمنًا ولا بديلًا لحساس البصمة؛ لا يوجد مسح فوتوغرافي لإصبع المستخدم.
- الاختبارات البرمجية لا تعوض تجربة حقيقية على iPhone وAndroid عبر HTTPS قبل الإطلاق.
